# Physics Provenance — measured golden references (WS6)

Status: delivered 2026-08-22. Companion to `fixtures/physics/golden-maneuvers.v2.json`
and `docs/physics-validation.md` (v1). Governing plan:
`docs/rl-platform-hardening-plan.md`, workstream WS6.

## What changed

Golden maneuvers must not be validated by numbers generated by the engine they
validate. v2 of the fixture adds a per-case `provenance` field:

| provenance       | meaning                                                        | CI   |
|------------------|----------------------------------------------------------------|------|
| `measured-carla` | executed against CARLA 0.9.16 as the physics oracle            | pass |
| `published-data` | cited external figure (regulatory, standard, or compendium)    | pass |
| `engine-derived` | solver self-check, or oracle not yet achievable — no external truth claimed | **pinned** |

CI teeth (`golden-maneuvers-provenance.test.ts`): every entry must declare a
provenance; every reference row carries its own provenance and may never be
`engine-derived`; engine-derived entries are only tolerated inside the fixture's
`documentedEngineDerivedIds` pin list — any new engine-derived entry (or stale
pin) fails the test. The pinned set is exactly the solver self-checks plus the
two maneuvers whose oracle runs did not yet produce valid numbers (below).

## Oracle

Tool: `tools/physics-oracle/carla_oracle.py` (own runner; the existing
`adapters/carla-bridge` was read-only for this workstream).

* CARLA server 0.9.16 (`carlasim/carla:0.9.16`, docker), client 0.9.16.
  Local host: RTX 5080 box, server in GPU container with rendering disabled
  (`no_rendering_mode`) — a physics-only oracle.
* Client note: the `carla==0.9.16` wheel segfaults in `get_world()` on this
  Ubuntu 24.04 host glibc stack, so the Python client runs in a slim
  `python:3.10` sidecar container sharing the server network namespace
  (`tools/physics-oracle`, container name `ws6-client`). Server version string
  is captured in every results file as evidence.
* Vehicle: `vehicle.lincoln.mkz_2020` (mid-size sedan stand-in for the generic
  passenger-car class). Fixed step 0.02 s — deliberately equal to the
  platform's 20 ms tick. Synchronous mode, no traffic, dedicated server.
* Map selection is automated: junction-free straight chains are scanned from
  OpenDRIVE waypoints, probe-driven station-by-station (speed retention + free-fall
  detection), and the longest fully clear window is used.

Raw evidence: `tools/physics-oracle/results/oracle-ground.json`,
`oracle-dlc.json`, `oracle-skidpad.json`, `oracle-step.json` — each carries
`carlaServerVersion`, map, vehicle blueprint, dt, per-maneuver records and
error blocks.

## Honest gaps (all pinned in `documentedEngineDerivedIds`)

1. **constant-radius-skidpad** — the Town03 roundabout lane-follower chased
   junction-interior waypoints: reported radius 0.7 m and >1 g sustained at
   24 km/h, which is kinematically impossible, so the samples were rejected.
   A proper constant-radius site (large open asphalt or a clean roundabout
   loop with closure detection) is the missing prerequisite.
2. **step-steer** — at 80 km/h and even 50 km/h, small steer steps eventually
   left the probed corridor and met roadside obstacles before settling;
   yaw-gain needs a large-area site (skidpad / airfield).
3. **double-lane-change dynamics** — course infrastructure and controller are
   complete and executed (evidence in `oracle-dlc.json`: entry speed reached,
   gates A/B within width at 40 km/h); a collision-free full-course pass is
   still needed before a peak-lateral-g band can be claimed.
4. The six non-physics self-checks (numerics convergence, determinism,
   friction sweep, split-μ, collision onset timing, throughput) never had
   external references; they remain solver assertions and are now explicitly
   labeled `engine-derived`.

None of these gaps is papered over with invented numbers: the test fails if an
engine-derived maneuver gains reference rows, or if a new one appears without
being pinned.

## Notable engineering findings (for future oracle users)

* `carla.Vehicle.set_target_velocity` is a *one-shot* velocity injection, but
  teleporting a moving actor (`set_transform`) can glitch PhysX — wraps that
  preserve speed must be followed by a stability check before measuring.
* Gear 0 with `manual_gear_shift` in CARLA is reverse, not neutral; there is no
  clean neutral-coast protocol, which is why the coastdown row documents a
  protocol divergence instead of forcing comparability.
* Probe-based clear-window detection (speed retention + free-fall detection
  after suspension settle) is required: nominal "straight" chains in Town04
  contain banked curves, hills and invisible blockers; Town01_Opt's grid gave
  the longest verified-clear stretch (285 m).
